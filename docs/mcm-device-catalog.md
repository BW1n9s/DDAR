# MCM 设备目录选择（用户修订，2026-10-21）

此文取代初始需求中“B 必须从玩家背包选择”的部分，其他核心目标继续有效。

## 新流程

1. 从玩家背包选择普通 Armor A，不要求穿戴。
2. 从已加载的 DD／DCL 等设备目录选择 B，不要求 B 已在玩家背包或已穿戴。
3. 保存外观映射；以后其他 Mod 正常装备 B 时生效。DDAR 不负责发放、装备或解锁 B。

当前 Phase 0 已去掉 B 在背包中的前置检查，但仍通过配置指定单组候选，
还没有 MCM 目录界面。该界面在核心显示／恢复实验通过后实现。

## 目录与身份

- 目录按当前实际加载的插件和最终覆盖记录建立，不只列 DD 四个主文件；包括有效的 DCL 及其他 DD 扩展设备。
- 只有与 DD NG 运行时数据库核对的 Inventory／Rendered 关系，才能作为 B。
  普通 Armor 上有 DD 效果 Keyword 不足以入选。
- B 的名称与插件来源展示 Inventory 设备；用于外观及槽位判断的是 Rendered 设备。
- Inventory 设备常常没有 Armor 槽位，不能据此把它排除。
- 如果多条 Inventory 共用同一 Rendered，需显式提示共享关系，不能承诺只影响其中一个 Inventory 的显示。
- 构建目录应缓存并分批处理，避免菜单打开时扫描完整 DD 数据库导致卡顿。
  验证方法必须避免对未确认 Inventory 执行会插入数据库项的正查 API。

## 多槽位筛选

MCM 展示完整集合，例如 A Armor `49`、B Rendered Armor `49,58`、B ARMA `52,58`。
第一层按 Rendered Armor 槽位分类：完全匹配、部分相交、不相交。
默认优先显示完全匹配；部分相交明确标记差异，不自动称为可替换。
ARMA、NIF 分区、性别／种族、多 ARMA 与其他已穿设备冲突另行校验。
默认 Safe Mode 只允许已验证的兼容组合，不能靠任意槽位相交就放行。

多槽位属于正式设计范围；当前实验限制单 ARMA 腰带仅用于验证核心路径，
不应把这一临时限制写成最终产品只支持单槽位的要求。

## 后续验收

- B 不在背包也能出现在目录，登记不会添加／穿戴它。
- 同一候选仍需解析真正 Rendered 并显示完整槽位集合。
- DD／DCL 自动装备 B 后再验收显示、锁定、恢复。
- 多槽位候选不能漏报额外占用、ARMA 分区或已穿装备冲突。
- 插件失效、加载顺序变化和共享 Rendered 必须有正确提示与安全跳过。
